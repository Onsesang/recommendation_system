# Experiment 23 — Tactile-conditioned retrieval

Generated by `scripts/04_report.py` from `results/*.csv`.

---

## 1. Research question

> *Does better tactile prediction translate into better product search?*

This is deliberately separated from next-item recommendation. Here the user
**states** a tactile preference ("a soft sweater", "a thin garment that is not
rough"), so the tactile attribute is the query, not a latent taste we have to
infer.

---

## 2. Query construction

Queries are enumerated from the taxonomy programmatically — none are hand-written
— and admitted only on pool size and class balance, never on how any system scores
them (`scripts/common23.py::build_queries`).

| family | meaning | test queries |
|---|---|---:|
| A | single tactile attribute, global pool | 8 |
| B | category + tactile, global pool (relevance needs **both**) | 48 |
| C | tactile **within one category** — the category shortcut is removed | 24 |
| D | two tactile attributes at once | 19 |
| E | **negative** tactile ("not rough") | 8 |
| | **total** | **107** |

Admission thresholds, fixed in advance: pool ≥ 30, relevant ≥ 8,
irrelevant ≥ 8.

### Why family E is legitimate here

The task rules forbid treating "the review did not mention rough" as
`rough = negative`. This dataset does not do that.
`experiments/12_.../scripts/build_targets.py` writes a negative for an attribute
**only** when a reviewer explicitly asserted its declared incompatible counterpart:

`soft↔firm`, `smooth↔rough`, `non_elastic↔elastic`, `thin↔thick`,
`flexible↔stiff`, `warm↔cool`, `spongy↔crisp`

All eight compared attributes sit in such a validated bipolar pair, so
"not rough" has real ground truth — a reviewer said *smooth*. Silence remains
UNKNOWN throughout.

### Ground truth and the UNKNOWN rule

For a query constraining attributes S, the candidate pool is the set of **locked
test** products whose label is KNOWN for every attribute in S. Products with no
evidence are **removed from the pool entirely** — neither relevant nor irrelevant —
so a system is never punished for ranking an item we simply know nothing about.

---

## 3. Systems compared

Tactile scorers reuse the cached Exp22 per-attribute probabilities, so the two
experiments are scored from identical model outputs. One extra system is included
because it is what a deployed search box would actually do:
**FashionCLIP text-image**, which embeds the query *sentence* and ranks images by
cosine similarity.

**Ranking rule, identical for every system.** A positive constraint on attribute
`a` scores `P(a)`; a negative constraint scores `1 - P(a)`. Multi-constraint
queries are combined by a single aggregator selected on **development-split**
queries by macro NDCG@10 averaged over all systems — so no system gets a bespoke
combination rule:

| aggregator | development macro NDCG@10 |
|---|---:|
| `mean_probability` | 0.4741 |
| `mean_log_probability` | 0.4766 |
| `min_probability` | 0.4666 |

Selected: **`mean_log_probability`**, applied unchanged to every system on test.
Ties are broken by one fixed seeded permutation shared by all systems.

### The central finding

**Last2 (ours)** leads globally at NDCG@10 0.4738, and
**Last2 (ours)** leads within category at 0.8290.

The instructive contrast is the natural-language search box. Globally,
FashionCLIP text-image reaches 0.4561 — close to
the best tactile model, and it would be easy to conclude that a plain sentence
search is competitive. Within a category it falls to
0.5609, a gain over the no-pixel control whose
95 % CI **includes zero**
([-0.0552,
+0.1000]).

So most of the sentence-search system's apparent ability was category matching.
The review-supervised predictor keeps a large, significant margin once that route
is closed. **This is the strongest positive evidence in the project that tactile
supervision buys something a generic text-image model does not have.**

Family **B** is where the tactile models lose badly to sentence search, and the
reason is structural rather than a defect: a B query demands the right *category*
**and** the right feel, while a tactile score carries no category information at
all. The design consequence is concrete — an agent should filter by category first
and rank by tactile second, not expect one tactile score to do both. We report it
rather than dropping the family.

## 9. Connection to Experiment 22

Exp22's Track A ordering (Last2 > FabricVST-B > SigLIP2 > zero-shot CLIP >
category-only) is preserved in same-category retrieval. That is **Case 1** of the
task's decision table: review-supervised tactile learning gives better prediction
*and* better retrieval, and the two rankings agree.

Note also **Case 3 does not occur**: FabricVST-B, which is degenerate on its own
internal metrics, does not outrank Last2 here either.

---

## 10. Limitations

1. Ground truth is Qwen-extracted **pseudo-labels** from reviews, not human
   relevance judgements. This measures agreement with review-derived labels.
2. The same locked test split has been observed by earlier experiments in this
   project, so this is **locked post-hoc exploratory**, not a fresh confirmatory
   test.
3. Same-category evaluation rests on 24 queries; the CIs are
   correspondingly wide and are reported rather than smoothed over.
4. The 11 categories are a title-keyword heuristic, not a validated taxonomy.
5. Bootstrap is over queries, so it captures query sampling, not label noise.

---

## 11. Conclusion

1. Tactile prediction quality **does** transfer to explicit tactile retrieval.
2. The advantage survives removal of the category shortcut, where a plain
   sentence-search baseline does not.
3. Tactile scores alone cannot satisfy category constraints — a deployed agent must
   compose category filtering with tactile ranking.
4. Negative ("not rough") queries are answerable here, because this dataset records
   genuine opposite-evidence negatives rather than inferring them from silence.
