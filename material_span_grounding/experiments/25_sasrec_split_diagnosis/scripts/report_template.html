Experiment 25 · Amazon_Fashion 2023 · SASRec

SASRec 첫 후보 검색은 왜 인기도 수준에 머무르는가

정답을 추천 가능한 옷으로 제한하고, 데이터를 자르는 세 가지 방식으로 SASRec을 다시 학습해 측정했습니다. 설정마다 시드 {{N_SEEDS}}개를 돌렸고, 모든 순위는 전체 상품을 대상으로 매겼습니다(full ranking). 이미 본 상품은 제외했습니다.

2026-09-30 · experiments/25_sasrec_split_diagnosis · RTX 3060

결론

  1. 코드 버그가 아니라 데이터 구조의 문제입니다. 같은 SASRec 코드를 MovieLens-1M에서 돌리면 논문 수치가 그대로 재현됩니다(HR@10 {{ML_S_HR}}, 논문 0.8245). Amazon_Fashion에서는 test 정답의 {{COLD_LOO}}가 학습에서 한 번도 학습되지 않는 상품입니다. ID 기반 모델은 이런 상품을 원리상 후보에 올릴 수 없고, 실제로 cold 정답의 Recall@500은 모든 설정에서 0입니다.
  2. 정답을 추천 가능 상품으로 제한해도 거의 변하지 않습니다. last_out 기준 Recall@500은 {{V1_R500}}에서 {{REC_R500}}로 조금 오를 뿐입니다. 추천 불가 정답(38.5%)은 평가 기준을 서비스에 맞추는 문제이지, 성능 병목은 아닙니다.
  3. 세로(시점 기준)나 가로(사용자 분할)로 자르면 Recall@500이 5~6%로 오르지만, 어느 방식에서도 SASRec 후보는 인기도 목록보다 낫지 않습니다. last_out에서는 3개 시드 중 2개에서 인기도보다 유의하게 낮았고, 나머지 설정에서는 차이가 없었습니다. 자르는 방식은 warm 정답 비율과 평가의 현실성을 바꿀 뿐이고, 모델이 개인화된 후보를 찾게 해주지는 않습니다.
  4. 기존 학습 레시피에도 손해가 있었습니다. validation 성능이 epoch 1~4에서 최고점을 찍고 떨어지는데, 5 epoch마다 검증하면 이 최고점을 놓칩니다. 매 epoch 검증으로 바꾸자 test NDCG@10이 {{V5_NDCG}}에서 {{V1_NDCG}}로 올랐습니다.
  5. 개선 여지는 콘텐츠 기반 후보에 있습니다. 이미지 특징 kNN은 cold 정답도 {{KNN_COLD}} 찾아냅니다. SASRec 250개와 이미지 kNN 250개를 합치면, 후보 수는 똑같이 500개인데 recall이 {{SAS_LOO}}에서 {{UNION_LOO}}로 오릅니다.

교수님 질문: 가로로 자를까, 세로로 자를까

사용자를 행, 시간을 열로 놓은 표로 보면 차이가 분명합니다. 현재 실험(exp16·17·24)은 행마다 따로 자르는 last_out입니다. 세로로 자르면 모든 사용자를 같은 시점에서 자르고(공식 timestamp split, t1 = 2021-08-11, t2 = 2022-07-16), 가로로 자르면 사용자 자체를 학습용과 평가용으로 나눕니다. 교수님이 말씀하신 가로·세로가 이 해석과 같은지 한 번 확인해 주세요.

학습 쌍 = SASRec이 실제로 배우는 (이전 상품 → 다음 상품) 쌍의 수. warm 정답 = 정답 상품이 학습 쌍에 한 번 이상 등장해 embedding이 학습된 경우.

  • last_out은 리뷰가 1개뿐인 사용자 175만 명의 리뷰를 전부 test로 보냅니다. 그래서 전체 2,474,375건 중 6.4%만 학습에 쓰입니다. 또 test 사용자마다 자기 정답보다 늦은 시점의 학습 이벤트가 평균 {{LEAK}} 섞여 있어, 미래 정보가 새는 쪽(낙관적)으로 편향됩니다.
  • 세로(timestamp)는 미래 정보가 새지 않아 실제 서비스 상황에 가장 가깝습니다. 학습 이벤트는 14배로 늘어나지만 대부분 1건짜리 사용자여서, 학습 쌍은 4.7배만 늘어납니다. 대신 t2 이전 이력이 3개 이상이면서 t2 이후에도 구매한 사용자만 평가할 수 있어서 평가 사용자가 2,446명으로 줄고, 신뢰구간이 넓어집니다.
  • 가로(user holdout)는 warm 정답 비율이 2배(51%)로 가장 높습니다. 하지만 학습 사용자의 미래 행동이 그대로 학습에 들어가므로, last_out과 같은 누수가 있습니다.

정답을 추천 가능 상품으로 제한한 결과

last_out에서 test 정답의 38.5%는 액세서리·신발·가방처럼 에이전트가 추천하지 않는 상품이었습니다. 이 정답을 빼고, 순위도 추천 가능 상품 483,779개 안에서만 매겼습니다(recommendable_fashion_v1 기준).

성능을 떨어뜨리는 요인

결정적

극단적으로 희소한 데이터

사용자 2,035,490명 중 86.2%는 리뷰가 1개뿐이고, 상품 825,869개 중 59.8%도 리뷰가 1개뿐입니다. SASRec 논문들이 쓰는 5-core로 거르면 이벤트가 0건이 되고, 3-core로 걸러도 12,490건(사용자 2,223명)만 남습니다. 공식 벤치마크에 Amazon_Fashion 5-core가 없는 것도 이 때문입니다. 다음 상품 예측을 배울 쌍이 last_out 기준 80,735개뿐입니다.

결정적

정답의 대부분이 학습되지 않은 상품 (cold item)

last_out test 정답의 {{COLD_LOO}}는 학습 쌍에 한 번도 나오지 않은 상품입니다(학습 등장 0회만 따져도 {{TC0}}). 이 상품들의 embedding은 초기값 그대로라서, cold 정답의 Recall@500은 모든 설정·시드에서 0.00%입니다. 반대로 warm 정답만 보면 SASRec Recall@500은 11~26%입니다. 전체 점수가 낮은 이유는 이 비율로 거의 다 설명됩니다.

큼

모델이 인기도 목록으로 수렴

SASRec top-500의 {{OVERLAP}}(last_out), {{OVERLAP_UH}}(user holdout)가 인기도 top-500과 겹칩니다. 사용자 이력이 짧고(test 사용자 중앙값 3개) 학습 쌍이 적으면, 모델은 "많이 팔린 것"을 넘어서는 신호를 거의 배우지 못합니다. 이력이 길수록 나아지는지는 아래 표에서 볼 수 있습니다.

작음

손실 함수 (BCE → sampled softmax CE)

최근 연구에서 SASRec을 크게 개선한 CE 손실(음성 4,096개)로 바꿔 봤습니다. Recall@500은 user holdout·전체 학습에서만 약 0.5%p 올랐고, NDCG@10은 대부분 떨어졌으며, 시드 간 편차가 크게 커졌습니다. 학습 신호 자체가 부족해서 손실 함수로는 해결되지 않습니다.

SASRec 구현 검증

  • MovieLens-1M(사용자 6,040명, 이벤트 100만 건)에서 논문과 같은 설정으로 학습했습니다. negative 100개 샘플링 평가에서 HR@10 {{ML_S_HR}} / NDCG@10 {{ML_S_NDCG}}로, 논문 수치(0.8245 / 0.5905)와 일치합니다. full ranking에서는 HR@10 {{ML_FULL_HR}} / NDCG@10 {{ML_FULL_NDCG}}로, 공개된 재현 연구(NDCG@10 약 0.13)와 같은 범위입니다.
  • exp24 재현: 같은 last_out·전체 카탈로그 조건에서 인기도 NDCG@10 0.00281은 exp17b와 소수 다섯째 자리까지 같습니다. SASRec NDCG@10 {{V1_NDCG}}도 exp24 R0(0.00349)와 비슷합니다.
  • 평가에 쓴 이력에 정답이 섞인 경우는 없습니다(Amazon 공식 파일이 사용자–상품 중복을 이미 제거함). 순위는 exp17b와 같이 동점일 때 iid가 작은 쪽을 앞에 둡니다.

다음 단계 제안

첫 후보 단계에 SASRec 하나만 쓰는 구조로는 cold 정답을 찾을 수 없습니다. 후보 생성에 콘텐츠를 넣어야 합니다.
{{UNION_TABLE}}

학습 없이 사용자 이력 이미지(exp16 SMORE 512차원)의 평균과 코사인 유사도로 순위를 매긴 결과입니다. 합집합도 후보 수는 500개로 같습니다.

  1. 평가 프로토콜: 교수님 의도가 세로 자르기라면 공식 timestamp split을 주 평가로 쓰는 것을 권합니다. 누수가 없고 서비스 상황과 같습니다. 평가 사용자가 적으므로 시드 반복과 신뢰구간을 같이 보고해야 합니다.
  2. 후보 생성: SASRec(또는 인기도) 후보와 이미지·텍스트 kNN 후보를 합치고, 그 위에서 촉감 재정렬을 평가합니다. 합집합만으로 last_out 후보 recall이 {{UNION_GAIN}} 오르고, user holdout에서도 {{UNION_GAIN_UH}} 오릅니다. timestamp에서는 이미지 kNN이 약해 효과가 거의 없으므로, 텍스트 특징 등 다른 콘텐츠 신호도 함께 봐야 합니다.
  3. 콘텐츠 기반 순차 모델: 상품 ID embedding 대신 이미지·텍스트 특징으로 상품을 표현하는 모델(예: UniSRec, 이미지 인코더를 쓰는 SASRec)을 쓰면 cold 상품도 점수를 받을 수 있습니다.
  4. 보고 방식: 전체 점수와 함께 warm / cold 정답을 나눠서 보고해야, 촉감 정보가 어느 쪽에 기여하는지 드러납니다.
