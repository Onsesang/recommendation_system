v1.2 변경 사항 (v1.1 대비)
  • 대화 응답의 action: 표에 없는 값이 오면 respond처럼 처리하도록 규칙 추가 (앞으로 action이 늘어도 화면이 깨지지 않게)
v1.1 변경 사항 (v1 초안 대비)
  • 메인 서버를 RTX 3060으로 변경하고 고정 Base URL 확정. 예비 서버(A100)는 준비 중. 서버 전환 시 로그인·대화·장바구니가 이어지지 않는다는 점을 명시
  • 대화 action에 remove_from_cart(장바구니 빼기) 추가. cart_updated는 담기·빼기 모두에서 true
  • 에이전트 답변에서 촉감 수치·"높음/낮음"이 사라짐. 응답 예시 교체. recommendation_reason, 확률 숫자는 화면에 표시하지 않도록 명시
  • rate limit과 429 too_many_requests 추가. CORS는 등록된 여러 origin 허용
  • 응답 시간 실측값 갱신(중앙값 약 3초), 엔드포인트 수 18개로 정정, 오타·누락 오류 메시지 보완
  • AI 모델 gpt-5.4-mini 확정, 오류 시 gpt-5.4-nano 대체 (응답 형식 변화 없음)

개요

모든 API는 /agent/v1 아래의 JSON API이고, 로그인 후 받은 토큰을 Authorization: Bearer 헤더로 보냅니다.

항목값
메인 서버 Base URLhttps://onsesang-pc-server.tail065d88.ts.net (RTX 3060 서버, Tailscale Funnel 고정 주소)
예비 서버 Base URL준비 중 (A100 서버). 준비되면 전달
형식요청·응답 모두 application/json; charset=utf-8. 본문이 있는 요청은 Content-Type: application/json 필수
인증Authorization: Bearer {access_token}
CORS서버에 등록된 origin만 허용. 현재 등록: https://onsesang-front.vercel.app, http://localhost:3000, http://127.0.0.1:3000. 다른 개발·시연 origin은 알려주면 등록
대화 응답 시간중앙값 약 3초, 대부분 5초 이내, 드물게 10초 이상. fetch timeout은 60초 권장
그 외 API 응답 시간대부분 0.1초 미만 (회원가입·로그인은 약 0.3~1초)
요청 한도회원가입·로그인·대화 메시지에 한도가 있음. 아래 "요청 한도" 참고
AI 모델OpenAI gpt-5.4-mini. 오류가 나면 그 요청을 gpt-5.4-nano가 대신 처리하고, 둘 다 실패하면 로컬 모드가 답합니다. 어느 경우든 응답 형식은 같습니다
  • 로그인 응답은 cookie(HttpOnly; SameSite=Strict)도 함께 주지만, 프론트가 다른 도메인에서 붙으면 cookie는 동작하지 않습니다. Bearer 토큰을 쓰세요.
  • 서버 상태 확인: GET /agent/v1/health는 인증 없이 호출할 수 있습니다.
  • Tailscale에 접속한 기기로 테스트하지 마세요. 그런 기기에서는 Base URL이 내부 주소(100.x)로 풀려, 크롬이 Vercel 사이트의 호출을 내부 네트워크 접근으로 보고 차단하거나 권한을 묻습니다. 일반 사용자와 같은 조건은 Tailscale을 끈 기기입니다.

인증 API

회원가입과 로그인은 같은 형식의 응답을 돌려주고, 이 중 access_token을 저장해 이후 모든 요청에 붙이면 됩니다. 토큰은 30일간 유효합니다.

POST /agent/v1/auth/register

이메일 형식, 비밀번호 8~256자, 이름 1~80자를 검사합니다. 성공하면 201과 함께 바로 로그인 상태가 됩니다.

POST /agent/v1/auth/login

요청은 { "email", "password" }이고 응답은 회원가입과 같은 형식(200)입니다. 이메일이나 비밀번호가 틀리면 401 이메일 또는 비밀번호가 올바르지 않습니다.가 옵니다. 너무 자주 시도하면 429가 옵니다.

POST /agent/v1/auth/logout

본문 없이 토큰 헤더만 보냅니다. 응답은 200 { "status": "logged_out" }이고, 그 토큰은 이후 401이 됩니다.

GET /agent/v1/auth/me

응답은 200 { "user": { "user_id", "email", "display_name", "created_at" } }입니다. 앱을 다시 열 때 저장된 토큰이 아직 유효한지 확인하는 용도로 씁니다. 401이면 로그인 화면으로 보냅니다.

상품 API

catalog는 825,840개 상품이고, 목록은 인기순으로 페이지를 나눠 줍니다. 촉감 값은 대부분 상품 이미지에서 예측한 확률이며 구매자 리뷰가 아닙니다.

GET /agent/v1/products?page=1&page_size=30

이미지

  • remote_image_url(Amazon CDN)을 우선 쓰세요. 어느 서버에서든 같은 이미지가 나옵니다. 값이 빈 상품이 드물게 있으니 빈 값이면 대체 이미지를 보여주세요.
  • image_url(/images/{id}.jpg)은 상대 경로라 Base URL을 앞에 붙여야 합니다. 현재 메인 서버에는 이미지 파일이 없어 404가 옵니다. 쓰지 않는 것을 권장합니다.
  • 화면낭독기 사용자를 위해 <img alt>에는 title을 넣어 주세요.

대화 API

로그인 후 세션을 하나 만들고, 사용자 입력마다 messages를 호출합니다. 서버가 대화 맥락(직전 검색 조건, 보여준 상품 번호, 장바구니)을 기억하므로, 프론트는 session_id만 유지하면 됩니다.

  • 표에 없는 action 값이 오면 respond처럼 처리하세요(답변만 추가, 기존 목록 유지). 백엔드에 기능이 추가되면 새 값이 생길 수 있고, 그때도 화면이 깨지지 않도록 하기 위함입니다. 새 값은 명세 개정 때 알립니다. v1.2
  • "N번"은 products 배열의 순서(1부터)입니다. 상품의 rank 필드는 개인화 전 검색 순위라 화면 번호로 쓰면 안 됩니다.
  • products를 다시 정렬하지 마세요. 답변의 번호와 화면 번호가 어긋납니다.
  • cart_updated가 true면 담기·빼기 중 하나가 일어난 것입니다. 빼기는 수량만 줄일 수도 있으니 장바구니와 배지는 항상 GET /agent/v1/cart 결과로 그리세요. 서버가 cart_add·cart_remove 이벤트를 이미 기록했으니 프론트에서 다시 보내지 마세요.
  • message는 화면낭독기용 평문이고 줄바꿈(\n)이 들어 있습니다. 마크다운으로 해석하지 말고 white-space: pre-line으로 표시하세요. 새 답변 영역에는 aria-live="polite"를 권장합니다. 답변에는 촉감 확률 숫자나 "높음/낮음" 같은 등급어가 나오지 않습니다.
  • recommendation_reason, last2_predictions, personalized_score, score_breakdown은 화면에 표시하지 마세요. 내부 모델명과 확률 숫자가 들어 있는 디버깅용 값입니다.
  • 촉감 출처: tactile_target_source가 image_predicted_last2면 "이미지로 예측", review_grounded_overlay면 "리뷰 근거 있음"으로 표시합니다.
  • status가 insufficient_results면 조건에 맞는 상품이 없는 것이며 오류가 아닙니다.
  • tool_calls, referenced_product_ids, unsupported_concepts, cart_updated는 OpenAI 장애로 로컬 모드가 답할 때 없을 수 있습니다. 없으면 빈 배열, false로 처리하세요.
  • intent, routing, provenance는 디버깅용이라 화면에 보여줄 필요가 없습니다. provenance.llm_model은 실제로 답한 모델(gpt-5.4-mini 또는 대체 모델 gpt-5.4-nano)입니다.
  • 전송 중에는 로딩을 보여주고 중복 전송을 막아 주세요. 한 턴에 보통 3~5초 걸립니다.

행동 이벤트 API

상품을 보고 누른 기록을 보내면 다음 추천의 개인화에 반영됩니다. 같은 event_id를 다시 보내면 중복 저장하지 않으므로, 재시도해도 안전합니다.

POST /agent/v1/events

// 요청
{
  "event_id": "evt_프론트에서_만든_uuid",
  "event_type": "product_click",
  "product_id": "B01CEC78VA",
  "session_id": "shop_8627884b...",
  "context": { "rank": 1 }

// 응답: 새로 저장 201, 이미 있던 event_id 200
{ "event_id": "evt_5bbfce9697c64cc6bfe8026e2de81be4", "created": true }

event_id · session_id · context는 선택입니다. event_id를 생략하면 서버가 만들지만, 중복 방지를 위해 프론트에서 만들어 보내는 것을 권장합니다.

event_type보내는 시점context
product_impression상품 카드가 화면에 처음 보일 때 (상품당 1회){ "rank": 1 }
product_click상품 상세를 열 때{ "rank": 1 }

cart_add / cart_remove보내지 마세요. 장바구니 API와 대화가 자동으로 기록합니다—

context.rank에는 화면 번호(products 배열 순서)를 넣으세요. 목록에 없는 event_type은 400, 없는 product_id는 404입니다.

취향 API

대화에서 "얇은", "검은색" 같은 조건이 나오면 서버가 취향으로 자동 저장하고, 다음 추천에 반영합니다. 프론트는 "내 취향" 화면에서 조회·수정·삭제만 하면 됩니다.

GET /agent/v1/preferences

{
  "items": [
    {
      "preference_id": "pref_1710ba35e2f048a88088f89502c12519",
      "scope_category": "dress",
      "attribute_type": "tactile",
      "attribute": "thinness",
      "direction": "more",
      "strength": 0.65,
      "confidence": 0.75,
      "source": "chat_auto",
      "source_text": "안 까끌하고 얇은 여름 원피스 찾아줘",
      "active": true,
      "created_at": "2026-09-24T15:18:17.571009+00:00",
      "updated_at": "2026-09-24T15:18:17.571009+00:00"
    }
  ],
  "auto_save": true
}
필드값
scope_category적용되는 옷 종류. null이면 전체
attribute_typetactile(촉감), color(색상), style(스타일)
directionmore 더, less 덜, avoid 피함, must_have 반드시
strength, confidence0~1 (내부 값. 화면에 숫자로 보여줄 필요 없음)
source_text저장의 근거가 된 사용자 발화. 로그·분석 도구에 보내지 마세요

PATCH /agent/v1/preferences/{preference_id}

direction, strength, confidence, active만 바꿀 수 있습니다. 예: { "strength": 0.5 } 또는 { "active": false }. 응답은 수정된 취향 하나이고, 다른 필드를 보내면 400입니다.

DELETE /agent/v1/preferences/{preference_id}

응답은 200 { "status": "forgotten", "preference_id": "pref_..." }입니다.

요청 한도 추가

공개 서버 보호와 비용 관리를 위해 아래 한도가 있습니다. 넘으면 429 too_many_requests와 Retry-After(초) 헤더가 옵니다. CORS에서 Retry-After 헤더를 읽을 수 있습니다.

대상기준한도
POST /auth/registerIP당1시간에 5회
POST /auth/loginIP당10분에 10회 (실패 포함)

// 응답 429 (헤더 Retry-After: 600)
{ "error": { "code": "too_many_requests", "message": "요청이 너무 많습니다. 600초 후 다시 시도해주세요." } }

오류 형식과 상태 코드

모든 오류는 같은 형식입니다. 인증·요청 한도 오류의 error.message는 한국어라 그대로 보여줘도 되지만, 일부 입력 오류는 영어입니다(예: Unknown product_id: …, quantity must be between 1 and 20, Route not found). 사용자에게는 error.code별로 프론트가 정한 한국어 문구를 보여주는 것을 권장합니다.

응답 없음·연결 실패—서버 다운아래 "서버 전환" 참고
  • OpenAI가 장애여도 대화 API는 로컬 모드로 200을 돌려줍니다. 오류로 처리하지 마세요.
  • 촉감 근거가 비어 있거나 image_predicted_last2인 것도 오류가 아닙니다.
  • 토큰, 대화 원문, source_text는 콘솔·분석 도구에 남기지 마세요.

서버 전환 수정

현재 메인 서버와 예비 서버는 데이터(계정·토큰·대화·장바구니·취향)를 공유하지 않습니다. 예비 서버가 준비되더라도 동기화가 생기기 전까지는 다음과 같이 동작합니다.
  • 예비 서버로 넘어가면 기존 토큰은 401입니다. 다시 로그인(또는 가입)해야 합니다.
  • 기존 session_id는 404입니다. 새 세션을 만들어야 하고, 대화 기록·장바구니·취향은 이어지지 않습니다.
  • 대화 메시지 전송은 같은 session_id로 다른 서버에 재시도하지 마세요.

전환 판단은 GET /agent/v1/health에 응답이 없을 때로 합니다. 예비 서버 Base URL과 동기화 여부는 준비되는 대로 이 문서에 반영합니다.
